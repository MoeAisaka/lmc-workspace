# 主控与执行：项目统一规则

本项目的单一规则来源；AGENTS.md、CLAUDE.md 只引用它。主控保留直接执行能力，角色不决定工具权限。显式用户权限与平台沙箱始终有效。

## 路由与质量

- 默认 DIRECT：主控连续调查、实现、验证、交付。小任务、未知根因、关键设计未定、高耦合或难验收的任务不委派。
- DELEGATE 仅在用户授权、核心方案/边界/验收清楚、次级模型有该任务类型资格且预计总成本和耗时受益时使用。新组合标实验，不假定合格。
- 一个任务一个稳定 ID、一个执行者；不派独立规划/测试/评审流水线，不让执行者再派生。交接只给必要上下文，不复制完整会话。
- 主控一次集中验收，最多一次集中退回。第二次交付仍失败、设计失配或预算耗尽，保全工件后主控安全接管；不换节点、改 ID 或重置 attempt 规避上限。
- 同版本可核实的测试证据复用；没有新改动/失败/证据，不重复测试、报告或模型轮询。控制回执不要求回复。

## 产品执行边界

- Claude/Codex 共用 spawn_worker/assign_task 入口。出生必须显式 model/effort；派发还必须有 goal/scope/acceptance/budget_minutes。不得继承默认模型。
- budget_minutes 为 1–1440 的整数，从首次派发开始计算，返工共享同一截止时间且不可延长。过期拒绝后续派发；不杀进程、不假装能硬限订阅额度或打断当前模型回合。
- 每个任务最多 attempt 1/2；派发前严格保存 delegationLedger，失败不发信。同任务不换执行者，**唯一例外是执行单元额度耗尽**（报告 `blocked: quota`）：此时可同 ID 换手到另一引擎/模型/机器，attempt 照常累加、不因换手重置，并告知用户哪个单元跑干了。这与本节上文「不换节点、改 ID 或重置 attempt 规避上限」一致——换手是因为该单元已经跑不动，不是为了多拿一次机会。重复投递复用同一内容身份，不能用旧 dispatch_id 携带新内容绕过。
- 限制记录独立于 40 行看板，跨进程重启/看板淘汰保留；最多保留 256 个任务，达到上限后拒绝新增委派，继续 DIRECT，不静默清空限制。
- 现有控制回执不启动用户消息回合，报告按业务身份去重；这是既有协议，不声称跨所有故障 exactly-once。
- 这些是正常产品入口约束，不是对恶意修改元数据/手写任务邮件/改任务 ID 的安全沙箱。语义上的“同一个问题”及模型资格仍需主控判断，不能宣称程序已自动识别。
- 旧任务只可按尚存看板信息保守续接；已淘汰的升级前历史无法追溯重建。旧 Agent 不具备新限制，必须升级才可声明其入口受控。

## 配置与预算记录

明确记录实际模型 ID/effort，不用提示词冒充配置切换。Astra/Fable 与次级额度池分账；计入规划、交接、执行、验收、返工和接管。缺少真实 usage 记 unknown，不把 API 估价/token 当订阅额度。没有同类 DIRECT 对照不声称省额度、省时间；不为测量重复做整项任务。

## 发布与回退

区分已实现、已验证、已部署和运行态待验。仅在已授权机器通过现有软升级流程发布；不强停活动会话、不复制凭据。失败保留当前工件和持久限制记录，停新委派，以前一版本恢复运行选择。回退旧版不代表旧版仍执行新门禁，期间维持 DIRECT。
