# 主控与执行：项目统一规则

本项目的单一规则来源；AGENTS.md、CLAUDE.md 只引用它。以下流程与双机 `~/.agents/controller-policy.md` 的 global-v2.1.1（2026-10-04，用户确认的原提案及中枢模型手动选择补充）一致；产品门禁继续以本文为准。主控保留直接执行能力，角色不决定工具权限。显式用户权限与平台沙箱始终有效。

## 路由与质量

- 默认 DIRECT：主控连续调查、实现、验证、交付。小任务、未知根因、关键设计未定、高耦合或难验收的任务不委派。
- 中枢／主控的模型与思考层级以用户手动选择为准，不设固定型号或默认层级，不因角色或规则自行切换、要求改选，不把提示词当成实际配置切换。执行节点的显式 model/effort 要求及核心代码分工不用于约束中枢模型。
- DELEGATE 仅在用户授权、核心方案/边界/验收清楚、次级模型有该任务类型资格且预计总成本和耗时受益时使用。新组合标实验，不假定合格。
- 派单前主控做完决定表、归档表、入口清单，核对合同引用的规范段落仍有效，合同一次写全。执行中疑问攒批，真实阻塞及时报告，继续不受影响的工作。合同正文只留 goal、验收要点、约束和证据路径；回报给结论、数字、提交号和证据路径，不重复过程。产品入口要求的结构化字段仍须完整填写。
- 一小时内、改动集中的中小修改由主控直接做。锁序、事务边界、幂等为主的核心代码由主控自写，执行节点只做外围接线、测试、夹具和文档；或改派 Astra，仍按执行机器目录选择显式 model/effort，遵守原任务身份、预算和交付门禁。
- 一个任务一个稳定 ID、一个执行者；不派独立规划/测试/评审流水线，不让执行者再派生。交接只给必要上下文，不复制完整会话。
- 主控一次集中验收；需要独立复审时，一件事只派一轮。复审必修由主控直接修并用复审探针自验，不派第二轮复审；只有结构性失配才退回作者，仍最多一次集中退回。第二次交付仍失败或预算耗尽，保全工件后主控安全接管；不换节点、改 ID 或重置 attempt 规避上限。
- 同一时间最多两个执行节点，测试串行。计时类检查在发版前集中跑一次，不反复等安静时段；之后有相关改动、失败或证据缺口才补跑受影响检查。已在跑的任务自然收尾，超出上限时先停止新派，不强停活动进程。这是主控调度规则，不声称已有产品级并发硬限制。
- 同版本可核实的测试证据复用；没有新改动/失败/证据，不重复测试、报告或模型轮询。控制回执不要求回复。
- 主控按验收需要读取报告章节和证据，遇矛盾或证据不足再补读；长任务与取证由合格执行节点完成，记忆写要点，不为缩短上下文省略必要验收。

## 产品执行边界

- Claude/Codex 共用 spawn_worker/assign_task 入口。出生必须显式 model/effort；派发还必须有 goal/scope/acceptance/budget_minutes。从执行节点所在机器发布的模型目录选择，未验证的模型/任务组合标实验；不得继承默认模型或套用固定模型矩阵。
- budget_minutes 为 1–1440 的整数，从首次派发开始计算，返工共享同一截止时间且不可延长。过期拒绝后续派发；不杀进程、不假装能硬限订阅额度或打断当前模型回合。
- 每个任务最多 attempt 1/2；派发前严格保存 delegationLedger，失败不发信。同任务不换执行者，**唯一例外是执行单元额度耗尽**（报告 `blocked: quota`）：此时可同 ID 换手到另一引擎/模型/机器，attempt 照常累加、不因换手重置，并告知用户哪个单元跑干了。这与本节上文「不换节点、改 ID 或重置 attempt 规避上限」一致——换手是因为该单元已经跑不动，不是为了多拿一次机会。重复投递复用同一内容身份，不能用旧 dispatch_id 携带新内容绕过。
- 换手门禁要求当前执行者对当前 attempt/dispatch 的最新有效报告为 blocked 且原因为显式 quota；其他 blocked、rejected、进行中或旧报告不能换手。接任者须已绑定，原 budget/deadline 不变；证明保存在持久账本中，后续有效报告/审核清除。
- 限制记录独立于 40 行看板，跨进程重启/看板淘汰保留；最多保留 256 个任务，达到上限后拒绝新增委派，继续 DIRECT，不静默清空限制。
- 中枢迁移携带账本，同 ID 取较大 attempt、较早 deadline、较小 budget。容量超限或同 attempt 所有权冲突保留限制并拒绝派发；迁移标记冻结旧中枢新增委派，部分失败仅重试同目的地，不清空旧账本或制造两个所有者。
- 现有控制回执不启动用户消息回合，报告按业务身份去重；这是既有协议，不声称跨所有故障 exactly-once。
- 双方协商 Agent Mail v3 时，取信不标记，配置/看板与收件凭据严格持久化、会话消息以稳定 localId 确认存储后才 ACK。重取同 id 只补未完成步骤，不重复启动回合；queued/refreshing 继续收件。旧中心保留取即标记与待刷新暂停行为；完整兼容及上线顺序见 [收件说明](reliable-agent-mail.md)。
- 这些是正常产品入口约束，不是对恶意修改元数据/手写任务邮件/改任务 ID 的安全沙箱。语义上的“同一个问题”及模型资格仍需主控判断，不能宣称程序已自动识别。
- 旧任务只可按尚存看板信息保守续接；已淘汰的升级前历史无法追溯重建。旧 Agent 不具备新限制，必须升级才可声明其入口受控。

## 配置与预算记录

明确记录实际模型 ID/effort，不用提示词冒充配置切换。Astra/Fable 与次级额度池分账；计入规划、交接、执行、验收、返工和接管。缺少真实 usage 记 unknown，不把 API 估价/token 当订阅额度。没有同类 DIRECT 对照不声称省额度、省时间；不为测量重复做整项任务。

## 发布与回退

区分已实现、已验证、已部署和运行态待验。仅在已授权机器通过现有软升级流程发布；不强停活动会话、不复制凭据。失败保留当前工件和持久限制记录，停新委派，以前一版本恢复运行选择。回退旧版不代表旧版仍执行新门禁，期间维持 DIRECT。
